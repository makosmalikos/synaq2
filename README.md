# SYNAQ — подготовка к РФМШ · НИШ · БИЛ

React/Vite-приложение для учебной практики, пробных экзаменов, диагностики и кабинета родителя. Данные аккаунтов и прогресс хранятся в Firebase; создание детей, оплата, AI и действия дуэли проверяются сервером.

## Локальный запуск

Для разработки и CI используйте Node.js из `.nvmrc` (`nvm use`). Версия закреплена,
поскольку последние знаки тригонометрических координат SVG и их SHA-256 могут
отличаться между версиями V8. Проверки иллюстраций сравнивают точные байты;
обновление Node.js нужно проверять вместе с воспроизводимостью этих файлов.
Команды выполняются из корня репозитория:

```bash
npm ci
npm ci --prefix frontend
cp .env.example .env
# Заполните необходимые серверные переменные в .env.
npm run dev
```

Приложение: `http://localhost:5173`, API: `http://localhost:4000`. Vite направляет `/api/*` на локальный Express. Сервер читает корневой `.env`; секреты никогда не должны иметь префикс `VITE_` или попадать в git.

Для раздельного запуска в двух терминалах:

```bash
npm run dev:api
npm run dev --prefix frontend
```

Фронтенд может показать лендинг и статические учебные материалы без API. Проверка тренировок и практики школьной программы, создание аккаунта ребёнка, действия дуэли, AI и оплата требуют запущенного API и настроенных интеграций. Отсутствующие серверные ключи возвращают ошибку конфигурации; это не означает, что действие выполнено. После изменения серверного кода перезапустите `npm run dev`: сервер Node не использует hot reload.

### Изолированный тестовый режим

Для проверки регистрации, детских аккаунтов и прогресса **без реальных пользователей и ключей** (нужна Java 21+):

```bash
npm run dev:emulators
```

Откройте `http://127.0.0.1:5175/app`. Это отдельный `demo-synaq-tests`: API — 4001, Auth — 19099, Firestore — 18080, все слушают loopback. Данные временные и исчезнут после остановки команды. Режим не читает `.env` и удаляет серверные ключи из окружения; реальные платежи и AI не настроены. Обычный `npm run dev` по-прежнему использует основной Firebase-проект.

Клиентский флаг эмуляторов разрешён только в локальной development-сборке. Сервер требует явный `SYNAQ_USE_EMULATORS=1`, demo-проект и два локальных адреса; смешанная конфигурация с production-ключами отклоняется. Не добавляйте эти флаги в production-окружение. `test:rules`, `test:journey` и `dev:emulators` используют одни порты, поэтому запускайте их по очереди.

| Путь | Назначение |

| `firestore.rules` | Отдельно публикуемые правила доступа Firebase |

## Учебные данные

`data.js` и `bank.js` содержат статический банк; импорт банка сам по себе не обращается в сеть. Учебный API ожидает явную загрузку дополнительных `bankTasks` перед подбором вопросов. При недоступности Firestore остаётся статический банк. Некорректные задания исключаются в карантин с причиной.

Кабинет родителя и экран прогресса используют лёгкий `topicCatalog.generated.js` вместо полного банка. После изменения статических заданий или правил нормализации обновите каталог и проверьте его:

```bash
node scripts/generate-topic-catalog.mjs --write
npm run validate:bank
```

Каталог содержит только ID задач и метаданные тем; его соответствие банку проверяется автоматически. Дополнительные административные задания подгружаются общим reader по требованию и кэшируются до перезагрузки страницы. Правила нормализации/карантина для каталога и тренировок общие.

Целевые форматы пробников заданы в `MOCK_SPECS`. Если предметов недостаточно, интерфейс показывает **сокращённый вариант**, фактическое число вопросов и время. НИШ соответствует официальной двухдневной структуре: 180 заданий и 240 минут. БИЛ соответствует опубликованным правилам приёма на 2026 год: 50 заданий по математике и логике, 10 по читательской грамотности, 110 минут. Банк покрывает не менее 10 полных последовательных пробников каждой школы без повторения вопроса; официальные образцы и авторское расширение SYNAQ хранятся раздельно. Новые учебные материалы должны проходить содержательную проверку: структурная валидация не доказывает правильность каждого решения.

Результаты сохраняются со стабильным ID попытки. При сетевой ошибке доступно повторное сохранение того же результата. Диагностика учитывает пропущенные задания, а задачи на обратную пропорциональность принимают точные дроби.

Неподтверждённый ответ тренировки сохраняется в `sessionStorage` отдельно по UID и восстанавливается после обновления той же вкладки. После подтверждения записи резервная копия удаляется. При недоступности browser storage показано предупреждение; закрытие вкладки может удалить несохранённый ответ. XP берётся из результата транзакции, включая часовой бонус; повторное подтверждение не начисляет его снова.

Тренировка и практика школьной программы используют `/api/learning`: сервер выдаёт сессию до ответа, сам проверяет ответ и атомарно обновляет результат, XP и дневной счётчик. Бесплатный лимит — 5 ответов в день по времени Asia/Almaty; задания, открытые в разных вкладках, не обходят его. В программе Standard сервер разрешает первые две темы каждой четверти и простую сложность. Повтор уже верно решённой задачи не даёт ещё 5 XP. Учебное время ограничено реальным временем серверной сессии, не пересекается между вкладками и учитывается максимум по 5 минут на задачу; один оставленный на час экран не даёт часовой бонус. Это не детектор внимания и не полноценная защита от ботов. Антиспам запуска сессий: 60/день Standard, 300/день Pro; незавершённая задача действительна 24 часа.

### SYNAQ Coins и выдача наград

Коины считаются отдельно от уровня: каждый подтверждённый сервером XP даёт один коин, а потраченные коины хранятся в `rewardWallets`. XP при обмене не уменьшается. Каталог: книга до 3 000 ₸ — 4 500 коинов; цифровой подарок Steam на $5 — 6 000; Brawl Pass — 7 500. При темпе 20 верных задач и одного часа подготовки в день это примерно 23, 30 и 38 дней. Награды выдаются не чаще раза в 30 дней после предыдущей выдачи.

Ученик отправляет заявку в разделе «Награды». Родитель подтверждает её в своём кабинете. Администратор видит подтверждённые заявки в разделе «Награды», связывается с родителем по указанной почте, проверяет возможность выдачи и **только после фактической передачи** нажимает «Выдано». Если награда недоступна, «Недоступно, вернуть коины» закрывает заявку и возвращает баланс. Отмена учеником и отказ родителя также возвращают коины. Пока поставка подарков не организована, не публикуйте магазин как обещание автоматической выдачи. Для Brawl Pass у Supercell есть ограничения на дарение молодым игрокам и в отдельных регионах; Steam может ограничивать дарение между странами. Проверяйте конкретный аккаунт перед выдачей.

Полный пробник и практика программы восстанавливают текущую попытку после обновления той же вкладки: вопросы, ответы, позицию и неподтверждённый результат. У пробника сохраняются дедлайн и пауза. Диагностика удаляет черновик только после резервной записи результата или подтверждения сервера; при отказе хранилища явно предупреждает о риске потери после закрытия страницы.

Семейный профиль восстанавливается при следующем входе, если Auth-аккаунт успел создаться, а запись Firestore — нет. Существующие подписки и имя не перезаписываются. Создание ребёнка повторяется с тем же `requestId` и PIN; сервер атомарно разрешает не более одного ребёнка в семье, в том числе при запросах из разных вкладок. PIN хранится только в памяти формы. Если страница была закрыта до копирования PIN, родитель может задать новый PIN в кабинете без потери прогресса ребёнка.

## Серверные API

| Маршрут | Назначение |
| --- | --- |
| `/api/child-create` | Создание нового ребёнка и серверная привязка к семье |
| `/api/child-password` | Смена пароля ребёнка подтверждённым родителем |
| `/api/checkout` | Проверка аккаунта родителя и тарифа, возврат ссылки Kaspi и суммы; доступ не выдаёт |
| `/api/webhook` | Проверка подписи Dodo для ранее оформленных подписок |
| `/api/entitlement` | Синхронизация семейного Pro-доступа |
| `/api/duel` | Создание, вход и проверяемые сервером действия дуэли |
| `/api/duel-award` | Однократное начисление XP по серверному результату дуэли |
| `/api/learning` | Серверные учебные сессии, оценка ответа, XP и дневной лимит |
| `/api/explain` | AI-разбор и перевод с проверкой пользователя и лимита |
| `/api/admin-login`, `/api/admin-task` | Администраторский вход и банк заданий |

Webhook получает исходные байты тела **до** JSON-парсера. Не ставьте общий body parser перед этим маршрутом: подпись должна проверяться по точному содержимому запроса. Неизвестные `/api/*` возвращают JSON 404.

Дуэль использует приглашение вида `/app?duel=ABC123`, а состояние обновляется через Firestore. Ответы и результат проверяет сервер; клиент не назначает себе очки или победу.

Новые платежи проходят по ссылке Kaspi из `shared/payments.json`. Подписка подключается вручную после проверки фактического платежа: при оплате обязательны email аккаунта ученика и телефон родителя. Сервер возвращает сумму из каталога тарифов, а клиент показывает её перед переходом. Ссылка не передаёт сумму или персональные данные в Kaspi и не подтверждает оплату. Открытие ссылки и параметры возврата не выдают доступ. Для пробников действует отдельная недельная покупка за 2500 ₸.

AI доступен только существующей семье или ребёнку с согласованными связями Auth/Firestore. Лимиты входа: 16 KiB для разбора, 96 KiB для пакета перевода; дневные количество и UTF-8 объём считаются атомарно и совместно для родителя и ребёнка. По умолчанию Free получает 5 запросов и 128 KiB, Standard — 15 и 256 KiB, Pro — 40 и 512 KiB в день. Кэшированный ответ не расходует квоту. Дополнительный общий суточный лимит проекта останавливает обращения к Gemini при достижении предела даже через множество семей.

Тренировки, пробные экзамены и полная адаптивная диагностика получают из API только условие и публичные метаданные текущей задачи. Правильные ответы, решения, адаптация сложности, проверка результата и начисление XP остаются на сервере. Итоги экзамена и диагностики записываются Admin SDK и не могут быть подменены прямой записью из браузера. Коллекция `bankTasks`, содержащая администраторские задачи с ответами, также закрыта от прямого клиентского чтения.

## Переменные окружения

Заполненный шаблон хранится только локально как `.env`; на Vercel задайте значения в настройках проекта.

| Переменная | Назначение |
| --- | --- |
| `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY` | Firebase Admin service account; ключ может содержать экранированные `\n` |
| `GEMINI_API_KEY` | Ключ AI-провайдера |
| `GEMINI_MODEL` | По умолчанию `gemini-3.1-flash-lite`; явное значение используется без автоматической подмены модели при ошибке |
| `EXPLAIN_FREE_DAILY_LIMIT`, `EXPLAIN_STANDARD_DAILY_LIMIT`, `EXPLAIN_PRO_DAILY_LIMIT` | Суточные лимиты AI-запросов Free/Standard/Pro; по умолчанию 5/15/40 на семью |
| `EXPLAIN_FREE_DAILY_INPUT_BYTES`, `EXPLAIN_STANDARD_DAILY_INPUT_BYTES`, `EXPLAIN_PRO_DAILY_INPUT_BYTES` | Суточные входные UTF-8 бюджеты; по умолчанию 131072/262144/524288 байт на семью |
| `EXPLAIN_GLOBAL_DAILY_LIMIT`, `EXPLAIN_GLOBAL_DAILY_INPUT_BYTES` | Общий предохранитель расходов Gemini на всю платформу; по умолчанию 1000 запросов и 20 MiB входа в сутки |
| `LEAD_GLOBAL_HOURLY_LIMIT` | Общий предел заявок с лендинга, по умолчанию 100/час; дополнительно действуют 5/IP и 3/контакт в час. Это предохранитель расходов, а не замена WAF/антиботу. На прямом Node-сервере клиентские proxy-заголовки не доверяются; на Vercel используется перезаписанный платформой IP. |
| `EXPLAIN_DAILY_LIMIT`, `EXPLAIN_DAILY_INPUT_BYTES` | Совместимые старые общие пределы; используются как верхняя база, если новые переменные не заданы |
| `ADMIN_EMAIL_1`, `ADMIN_EMAIL_2` | Разрешённые адреса администраторов |
| `DODO_PAYMENTS_API_KEY`, `DODO_STANDARD_PRODUCT_ID`, `DODO_PRO_PRODUCT_ID` | Только для сопровождения прежних подписок Dodo; для новых платежей Kaspi не нужны |
| `DODO_WEEKLY_MOCK_PRODUCT_ID` | Только для обработки ранее начатых платежей Dodo за недельные пробники |
| `DODO_WEBHOOK_SECRET` | Секрет webhook для прежних платежей Dodo |
| `DODO_ENV` | `test_mode` для тестовых платежей; другое значение включает live |

| `APP_URL` | URL приложения для возврата из оплаты |
| `PORT` | Порт локального API, по умолчанию 4000 |

Управление прежней подпиской доступно только семьям с `dodoSubId`, чтобы они могли отключить старое автопродление и посмотреть историю. Webhook и Customer Portal сохранены для этих подписок; новые Dodo checkout-сессии больше не создаются. Смена платного тарифа согласуется с поддержкой. Замена платёжной ссылки не отменяет уже действующее автопродление у прежнего провайдера.

## Проверки

```bash
node --test tests/*.test.*
npm run test:security # авторизация, спам, HTTP, платежи и AI; без реальных провайдеров
npm run test:rules # требует Java 21+; только локальный demo-проект
npm run test:journey # Auth + Firestore, реальные SDK и локальный API
npm run validate:bank
npm run validate:curriculum
npm run build --prefix frontend
npm run validate:build # запускать после сборки
npm run verify:release # публичные GET/HEAD к synaq.app после деплоя
```

`verify:release` проверяет прямое открытие четырёх маршрутов, согласованность
входной сборки, типы ответов JS/CSS из HTML и preload-карты и небольшие картинки
взрослых питомцев. HTML-заглушка вместо отсутствующего JS считается ошибкой.
Другой адрес можно передать через `npm run verify:release -- https://ваш-домен`.
Проверка не входит в CI до деплоя, не авторизуется, не меняет данные и не проводит
платежи. Она не заменяет проверку интерфейса, реального телефона и всех картинок.

`npm run check` выполняет тесты, валидацию данных, сборку и проверку загрузки. CI дополнительно запускает оба набора emulator-тестов. Проверки платежей и AI используют заглушки. `test:journey` выполняет настоящую регистрацию родителя, создание ребёнка через API, детский вход, потерю сетевого ответа учебного API, повтор сохранения, конкурентный дневной лимит, чтение прогресса родителем, конкурентное создание и восстановление PIN. Отдельно проверяется восстановление семьи после прерванной регистрации. Всё выполняется на временном demo-проекте; production-интеграции это не проверяет.

`validate:build` проверяет production manifest: лендинг и публичная диагностика не должны загружать Firebase/экзаменационный банк, а кабинет, Parent и Progress — банк вопросов. Для публичных страниц установлены gzip-бюджеты JavaScript. Шрифты сохраняют текущие семейства и веса, но внешняя CSS-загрузка больше не блокирует первый рендер.

Остаток `npm audit` в dev-дереве: `stream-json` и зависимый `firebase-tools` (одна moderate-уязвимость и агрегированная запись). До совместимого upstream-обновления не импортируйте недоверенные JSON через Firebase CLI. Не применяйте `npm audit fix --force`: предлагаемый откат CLI несовместим с текущим окружением. Production-зависимости проверяются отдельно: `npm audit --omit=dev`.

## Деплой

На Vercel выберите корень репозитория; `vercel.json` собирает `frontend/dist` через `npm ci`. Серверные переменные задаются отдельно от клиентской сборки. Для Kaspi дополнительные ключи не нужны. Если остались прежние подписки Dodo, сохраните их переменные и webhook `https://ваш-домен/api/webhook` до завершения обслуживания этих подписок.

**Деплой приложения не публикует Firestore Rules.** Обновлённые `firestore.rules` нужно проверить и опубликовать отдельно в том Firebase-проекте, к которому подключено приложение. Новые ограничения предполагают серверное создание связи ребёнка с семьёй, серверную запись Pro, результатов тренировок/XP и доверенного общего AI-кэша. Клиент, `/api/learning` и Rules должны выкатываться согласованно: новые Rules блокируют старые прямые записи тренировок, а старые Rules ещё позволяют обходить новый API. Перед публикацией проверьте существующие семейные связи и сценарии на эмуляторе; секреты, реальные платежи и удаление пользовательских данных не нужны для локальных тестов.

В Firebase Authentication включите Email/Password и Google, укажите реальные домены приложения в Authorized domains. Дополнительное историческое описание: `FIREBASE_SETUP.md`, `Synaq_BRD_PRD_TRD.md`; при расхождениях ориентируйтесь на текущий код и этот README.


### Пробники на лендинге и платформе

Лендинг содержит по одному фиксированному полноформатному варианту без регистрации: РФМШ — 30 заданий и 120 минут, БИЛ — 60 заданий и 110 минут, НИШ — 180 заданий и 240 минут. Наборы генерируются командой `node scripts/generate-public-mocks.mjs` и не меняются от недели к неделе. В кабинете варианты обновляются по понедельникам в 00:00 по Алматы. Pro включает доступ; разовая покупка за 2500 ₸ открывает три школьных варианта для семьи до конца текущей недели. Начатый тест сохраняет свой таймер и может быть завершён после смены недели.

Недельные пробники оплачиваются по той же ссылке Kaspi, доступ подключается вручную после проверки платежа. Кнопка «Уже оплатили? Проверить доступ» перечитывает серверный статус. Переход в Kaspi не записывает `paid` и не выдаёт подписку. Локальные проверки не совершают реальные платежи.

### Пополнение банка через админку

В разделе задач доступны редактор с предпросмотром, список административных
заданий с поиском и фильтрами и импорт CSV UTF-8 (шаблон скачивается в интерфейсе).
Excel-файл нужно сохранить в CSV; прямой импорт XLSX/PDF пока не поддерживается.
За одну загрузку принимается до 100 задач и до 1 МБ исходного CSV. Для выбора
ответа в столбце `answer` указывается полный текст правильного варианта.

Новые задачи и импорт сохраняются как черновики. После проверки условия,
ответа и решения администратор отмечает задачу проверенной, затем публикует.
В тренировки и автоматически собираемые пробники попадают только опубликованные
задачи; старые записи без статуса сохраняют прежнее поведение. Опубликованные
задания неизменяемы, чтобы не менять ответы в уже начатых попытках. Для похожего
задания используется копия с новым условием. Решения не проверяются математически
автоматически: содержательная проверка остаётся за преподавателем.

`/api/admin-task` проверяет актуальный admin claim и allowlist для чтения и записи.
Пакетный импорт атомарен: ошибочная строка или дубликат блокирует весь пакет.
Дубликаты определяются по школе, языку и условию с нормализацией регистра и пробелов
в статическом и административном банке. `bankTaskKeys` хранит серверные ключи
уникальности, защищающие от повторных/одновременных отправок. Редактирование
черновиков проверяет номер ревизии. Список загружается по 50 записей, поиск работает
по загруженным задачам. Черновик редактора автоматически сохраняется в браузере
под UID администратора; при недоступности хранилища интерфейс предупреждает.

## Кабинеты образовательных центров (B2B)

`/centers` открывает вход и кабинет центра. Ссылка «Для центров» есть на лендинге.
Аккаунт руководителя создаёт один центр.
Руководитель создаёт группы, приглашает преподавателей по подтверждённой почте и
назначает их группам. Преподаватель видит только свои группы; руководитель — весь
центр. При отключении преподавателя его группы переходят руководителю.

Для подключения учеников преподаватель создаёт код группы со сроком действия
7 дней и передаёт его родителям. Новый код отменяет прежний код этой группы.
Родитель создаёт обычный аккаунт ребёнка и вводит код в разделе «Подключение к центру»,
подтверждая доступ центра к имени, классу и результатам по назначенным темам.
Один ребёнок состоит в одной группе одного центра. Родитель может отозвать доступ;
прогресс ребёнка сохраняется. Преподаватель также может отключить ученика от группы.
Доступ к глобальной админке Synaq центрам не предоставляется.

Задание задаёт тему, 1–50 разных задач (не больше количества задач в теме) и срок
в ближайшие 30 дней (время Алматы). В кабинете ребёнка: «Задания центра», на телефоне
— «Задания» в нижнем меню. Кнопка задания открывает
тренировку по теме на оставшееся количество задач, исключая уже выполненные
в рамках задания вопросы. Выполнение считается по уникальным вопросам с
проверенным сервером ответом после назначения и подключения к группе. Неверные
ответы входят в количество выполненных задач; точность показана отдельно.
Повтор одной задачи не увеличивает выполнение. Практика школьной программы не
засчитывается в задания тренировки. Пересекающиеся задания по одной теме могут
учитывать один и тот же ответ. Это тематическая практика, а не фиксированный
экзаменационный вариант. Журнал показывает последние 30 дней, отмечает просрочку
и позднее завершение, поддерживает поиск ученика и выгрузку CSV. На телефоне журнал
показывает раскрывающиеся карточки учеников; на большом экране — таблицу.
Отключение ученика требует подтверждения в интерфейсе.

Подключённый ученик автоматически получает главную «Мой центр»: ближайшие занятия,
задания и прогресс своей группы. «Самостоятельно» сохраняет доступ к общей подготовке.
Режим определяется членством в группе, а не оплатой лицензии. После отключения
возвращается обычный кабинет. У родителя основным становится раздел «Учёба в центре»
с выбором ребёнка, расписанием, заданиями и результатами; «Общая подготовка» доступна отдельно.

В кабинете центра есть «Расписание»: занятия на конкретную дату (время Алматы),
длительность 15–240 минут, кабинет/адрес, HTTPS-ссылка и заметка для учеников.
Можно создать 1–12 еженедельных занятий на ближайшие 90 дней, перенести или отменить
отдельное будущее занятие. Пересечения в одной группе запрещены; одновременные правки
защищены версией записи. Отменённые занятия остаются видны. Преподаватель управляет
только своими группами; ученик и родитель читают расписание только своей группы.
Изменения загружаются при открытии раздела, возврате в окно или нажатии «Обновить».
Учёт посещаемости, автоматические напоминания и синхронизация с внешними календарями
в эту версию не входят. Расписание показывает прошедшую неделю и будущие занятия.
При более чем 1000 записях в этом периоде интерфейс явно предупреждает, что список неполный.
Обновление кабинетов сохраняет текущий экран во время запроса. Ошибка загрузки
одного ребёнка не скрывает успешно загруженные данные других детей.

В глобальной админке появился раздел «Центры»: администратор Synaq вручную задаёт
число мест (1–100), срок (до года) и активность лицензии после согласования условий
с центром. Эта форма не списывает деньги. Активная лицензия даёт подключённым детям
доступ уровня `pro` к тренировкам, школьной программе, пробникам и AI-объяснениям
с действующими серверными лимитами; уроки с наставником остаются отдельным тарифом.
Семейная подписка не изменяется и имеет приоритет, если её доступ выше.
Истечение/отзыв лицензии или выход из центра сразу учитываются учебными API и
обновляют интерфейс через Firestore. Без лицензии подключение до 30 учеников
доступно для организации пилота, а обучение идёт по их семейным тарифам.

Ограничения первой версии: до 30 групп и 20 сотрудников на центр, один центр на
аккаунт сотрудника, до 100 активных заданий за 30 дней на группу. В журнале читаются
первые 1000 ответов ученика с начала самого раннего отображаемого задания; при
превышении выводится явное предупреждение о неполных данных. Доступны последние
100 зарегистрированных центров в админке. Онлайн-оплата организаций, счета,
брендирование и импорт списков учеников ещё не реализованы.

Данные `centers`, `centerStaff`, `centerInvites`, `centerInviteRates` доступны
только через `/api/center`, проверяющий Firebase ID token и роль на сервере.
`centerSeats` читается только самим ребёнком, а `centerLicenses` — только ребёнком
с активным местом в соответствующем центре; клиентские записи запрещены.
Перед production-запуском **опубликуйте обновлённые Firestore Rules вместе с
приложением**. Серверный catch-all Vercel обслуживает `/api/center`, отдельная
serverless-функция не добавляется. Миграция семейных данных не требуется.

Проверки B2B:

```bash
node --test tests/center-service.test.cjs tests/center-model.test.mjs
FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:19099 FIRESTORE_EMULATOR_HOST=127.0.0.1:18080 node --test tests/center-emulator.test.cjs tests/rules.test.mjs
```

Вторую команду запускайте при работающем `npm run dev:emulators`. Она использует
только `demo-synaq-tests`, создаёт собственные тестовые аккаунты, проверяет полный
HTTP-сценарий до реального ответа в тренировке и не очищает общий эмулятор.

Для демонстрации интерфейса с вымышленными учениками при работающих эмуляторах:

```bash
SYNAQ_USE_EMULATORS=1 FIREBASE_PROJECT_ID=demo-synaq-tests FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:19099 FIRESTORE_EMULATOR_HOST=127.0.0.1:18080 node scripts/seed-center-demo.cjs
```

Тестовые данные создаются только в эмуляторах; данные для локального входа записываются в
`/tmp/synaq-center-demo.json`. Скрипт отказывается запускаться с production-конфигурацией.

## PWA: установка на главный экран

На главной странице и в кабинетах ученика, родителя и центра доступна кнопка
«На главный экран» (RU/KK). В браузерах с `beforeinstallprompt` она вызывает
системное подтверждение установки. На iPhone показывается инструкция для Safari:
«Поделиться → На экран Домой → Добавить». Автоматической установки без
подтверждения браузера нет. Предложение можно скрыть на 7 дней; постоянная кнопка
остаётся в меню ученика/центра, настройках родителя и подвале главной страницы.

Манифест, обычные и maskable PNG-иконки и Apple touch icon находятся в
`frontend/public`. Установленное приложение запускает `/app` и скрывает предложение установки
в standalone-режиме. В зависимости от браузера может потребоваться повторный вход.
Ярлык центра доступен через shortcut манифеста там, где браузер поддерживает shortcuts.

Service worker регистрируется только в production-сборке на HTTPS (или localhost).
Он сохраняет исключительно публичную страницу `/offline.html`. Задания, API,
результаты и личные данные в его кэш не записываются; для кабинета нужен интернет.
Обновление worker не перезагружает открытую тренировку: новая версия ждёт закрытия
старых вкладок. Vercel отдаёт worker без HTTP-кэша и исключает PWA-файлы из SPA rewrite.

Проверка: `node --test tests/pwa.test.mjs`, затем production build и
`node scripts/validate-build.mjs`. Финальную установку на физическом iPhone/Android
проверяйте после публикации на HTTPS; режим разработки не регистрирует worker.
