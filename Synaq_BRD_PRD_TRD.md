# Synaq — BRD · PRD · TRD

**Продукт:** Synaq (сынақ — «экзамен, испытание») — онлайн-платформа подготовки детей 10–12 лет к вступительным экзаменам в топовые школы Казахстана: РФМШ, НИШ, БИЛ.
**Версия документа:** 1.1
**Дата:** июль 2026

> О названии школ: БИЛ — лицеи «Білім-Инновация» (ранее известные как КТЛ, казахско-турецкие лицеи; после передачи фонду в 2016 году официальное название — БИЛ). В продукте используется «БИЛ».

# Часть 1. BRD — Бизнес-требования

## 1.1. Видение
Synaq делает подготовку к вступительным экзаменам в элитные школы Казахстана прозрачной и результативной. Сегодня подготовка идёт «вслепую»: репетиторы учат «в общем», а родитель не видит, по каким темам ребёнок реально проседает. Правда вскрывается только на экзамене — когда уже поздно. Synaq превращает подготовку в измеримый процесс: ребёнок занимается по формату конкретной школы, а родитель видит прогресс.

## 1.2. Проблема
- Конкурс в РФМШ, НИШ и БИЛ высокий (порядка 6–10+ человек на место).
- Подготовка дорогая и непрозрачная: репетиторы, «общая математика», отсутствие обратной связи для родителя.
- Нет инструмента, который готовит именно под формат конкретной школы и показывает слабые темы до экзамена.

## 1.3. Целевая аудитория
- **Основной плательщик:** родитель ребёнка 10–12 лет (5–6 класс), нацеленного на поступление.
- **Основной пользователь:** ребёнок 10–12 лет.
- **Гео:** Казахстан (Астана, Алматы в первую очередь), казахо- и русскоязычная аудитория.

## 1.4. Ценностное предложение
- Подготовка под формат конкретной школы, а не «в общем».
- Разбор каждой ошибки — ребёнок понимает, где ошибся.
- Мок-тесты в условиях настоящего экзамена.
- Прозрачный прогресс для родителя: какие темы сильные, какие слабые.

Ключевое сообщение: «Образование ребёнка — фундамент его будущего. А фундамент должен быть крепким».

## 1.5. Бизнес-модель
- **Подписка** (месячная / на период подготовки) на семейный аккаунт.
- Возможные тарифы в будущем: базовый (одна школа), расширенный (несколько школ, детальная аналитика), для образовательных центров (B2B).
- Пред-запуск: сбор лидов через waitlist-лендинг.

## 1.6. Конкуренты и отличие
- Частные репетиторы — дорого, непрозрачно, нет системности.
- Общие EdTech-платформы (Bilimland и др.) — не заточены под формат вступительных экзаменов конкретных школ.
- **Отличие Synaq:** узкий фокус на вступительных экзаменах РФМШ/НИШ/БИЛ + прозрачность для родителя.

## 1.7. Метрики успеха
- **Пред-запуск:** число записавшихся в waitlist, конверсия лендинга.
- **Активация:** доля семей, где ребёнок прошёл первый диагностический тест.
- **Вовлечённость:** DAU/WAU ребёнка, число решённых задач, число пройденных мок-тестов.
- **Ценность:** рост баллов в мок-тестах от недели к неделе.
- **Монетизация:** конверсия в платную подписку, удержание (retention), LTV.

## 1.8. Этапы вывода на рынок
1. **Пред-запуск:** лендинг + сбор waitlist, контент в Instagram/LinkedIn/Threads.
2. **MVP:** РФМШ (готова), тренировка + мок-тесты, семейные аккаунты.
3. **Расширение:** НИШ и БИЛ, детальная аналитика для родителя, реферальная механика.

## 1.9. Риски
- Ответы в банке задач должны быть выверены по официальному ключу школ.
- Использование логотипов/названий школ — только с учётом их прав (сейчас — текстовые бейджи, не логотипы).
- Детская аудитория — повышенные требования к приватности и безопасности данных.

# Часть 2. PRD — Продуктовые требования

## 2.1. Обзор продукта
Веб-приложение (адаптивное, mobile-first) с двумя ролями в рамках одного семейного аккаунта: родитель и ребёнок. Ребёнок готовится (тренировка + мок-тесты), родитель следит за прогрессом.

## 2.2. Роли
- **Родитель** — регистрируется по почте, выбирает целевую школу, создаёт аккаунт ребёнку, видит прогресс и результаты.
- **Ребёнок** — заходит по коду и PIN (без почты), решает задачи и проходит мок-тесты.

## 2.3. Пользовательский путь
1. Родитель заходит на лендинг → «Тіркелу».
2. Регистрируется (почта + пароль), выбирает школу (РФМШ / НИШ / БИЛ) карточками.
3. В кабинете создаёт ребёнка (имя, класс, PIN) → получает код.
4. Ребёнок входит по коду + PIN.
5. Ребёнок занимается: тренировка по темам, еженедельный мок-тест.
6. Родитель видит результаты и слабые темы.

## 2.4. Функциональные требования (MVP)

### Онбординг и аккаунты
- Стартовый экран: «Аккаунт құру» / «Аккаунтым бар» (по центру).
- Регистрация родителя в 2 шага: почта+пароль → выбор школы карточками (название, полное имя, классы, конкурс, статус «Дайын/Жақында»).
- Создание ребёнка родителем: код + PIN.
- Вход по ролям: родитель (почта или **через Google**) / ребёнок (код+PIN).
- При входе через Google аккаунт родителя создаётся автоматически (почта сохраняется).

### Тренировка («Дайындық»)
- Темы сгруппированы по блокам: **Математика** и **Логика**, с долей каждого блока в экзамене (напр. математика ~87%, логика ~13% — по числу задач).
- У каждой темы: название, число задач и **процент решённого** (прогресс-полоса). Без указания «уровня» (деңгей).
- Задача с открытым ответом (поле ввода) — соответствует формату экзамена.
- Кнопка «Тексеру» → верно/неверно + пошаговый разбор («толық талдау»).
- Таймер на каждую задачу. Проверка ответа терпима к формату (пробелы, %, запятая/точка, единицы).

### Мок-тест недели
- **Один вариант на неделю**, который система выбирает и сменяет автоматически (без списка вариантов).
- Экзаменационный режим: без обратной связи по ходу, жёсткий таймер, открытый ответ.
- После сдачи — балл и разбор по каждой задаче.
- Результат и полный разбор **сохраняются в раздел «Прогресс»** и доступны позже.

### Прогресс и кабинет родителя
- Ребёнок: сводка (решено задач, % верных, число мок-тестов) + **история мок-тестов**; по клику открывается сохранённый разбор (талдау).
- Родитель: список детей, результаты мок-тестов.

## 2.5. Вне MVP (следующие волны)
- НИШ и БИЛ (контент по их форматам).
- Диагностический тест на входе, определяющий персональный план.
- Адаптивная сложность в тренировке.
- Дуэли и лига (геймификация).
- Задачи с изображениями (чертежи) в полном объёме.
- Детальная карта прогресса и рекомендации для родителя.

## 2.6. Принципы UX
- Минимализм: одно понятное действие на экране, много воздуха, один акцентный цвет.
- Мобильный приоритет, крупные зоны нажатия (аудитория — дети).
- Открытый ответ, а не выбор из вариантов (как на реальном экзамене РФМШ).
- Разбор ошибки в стиле «убери лишнее → ключевая идея → шаги → совет».

## 2.7. Тематическая структура (РФМШ, 7 класс)
Приложение **школо-осознанное**: у семьи с выбранной школой (РФМШ или БИЛ) тренировка и мок-тест берут задачи именно этой школы. Школа выбирается родителем при регистрации и хранится у ребёнка.

Математика: уравнения и упрощение, числа и делимость, работа и производительность, части/отношения/движение, геометрия, вычисления и дроби, проценты, системы и неравенства.
Логика: последовательности, матрицы/аналогии, пространственное мышление, числовая/комбинаторная логика.

# Часть 3. TRD — Технические требования

## 3.1. Архитектура
Проект разделён на независимые части, деплой — одним проектом Vercel (монорепо):

- **frontend/** — React + Vite. Интерфейс (вход, тренировка, мок-тесты, кабинет).
- **backend/** — Node.js + Express. JSON API: банк задач, темы, мок-варианты, генераторы. Работает как serverless-функция на Vercel (`api/[...path].js` → Express-приложение).
- **landing/** — статический лендинг (сбор лидов / вход в приложение).
- **Firebase** — авторизация (Auth) и хранение результатов (Firestore).

Фронт обращается к бэкенду по `/api/...` на том же домене (без CORS и внешних переменных окружения). Авторизация и результаты — через Firebase напрямую из фронтенда.

## 3.2. Стек
- Frontend: React 18, Vite 5.
- Backend: Node.js, Express 4, CORS.
- Auth/DB: Firebase Authentication (Email/Password) + Cloud Firestore.
- Хостинг: Vercel (статика фронта + serverless-функция бэка).

## 3.3. Модель данных

### Банк задач (backend/data)
- **topics.js** — 12 тем: `{ id, block ('math'|'logic'), name (kk), nameRu }`.
- **questions.js** — тренировочный банк (все 8 вариантов РФМШ-2025, ~250 задач): `{ id, topic, difficulty (1–3), variant, num, statement, answer, solution, image? }`.
- **mockVariants.js** — мок-тесты: РФМШ-варианты собираются из банка по тегу `variant`; отдельный вариант БИЛ. Структура: `{ id, title, timeLimitMin, school?, questions:[...] }`.
- **bilQuestions.js** — задачи БИЛ (формат A–E). Поля: `{ id, school:'БИЛ', variant, num, topic, statement, options?, answer, correctLetter?, solution }`.
- **generators.js** — параметрические генераторы похожих задач (куры/овцы, две наценки, части по отношению, две трубы).

### Данные пользователей (Firestore)
- `families/{parentUid}` — `{ parentEmail, school, createdAt }`.
- `families/{parentUid}/children/{childUid}` — `{ name, klass, code, createdAt }`.
- `childIndex/{childUid}` — `{ parentUid, name, klass, school }` (школа — чтобы ребёнку показывать задачи нужной школы).
- `results/{childUid}/attempts/*` — попытки в тренировке `{ qid, topic, correct, secs, at }`.
- `results/{childUid}/mocks/*` — результаты мок-тестов `{ testId, title, score, gradable, total, review, at }` (review — для разбора в «Прогрессе»).

## 3.4. API (бэкенд)
Тренировка:
- `GET /api/training/topics?school=РФМШ|БИЛ` — темы с числом задач для школы.
- `GET /api/training/topics/:id/questions?mix=1&limit=N&school=...` — задачи по теме и школе.
- `GET /api/training/mixed?limit=N` — смешанная тренировка.
- `GET /api/training/generate?n=N&topic=X` — сгенерировать похожие задачи.

Мок-тест:
- `GET /api/mock/weekly?school=...` — вариант недели (автосмена).
- `GET /api/mock` — список вариантов.
- `GET /api/mock/:id` — вариант без ответов и разбора (как на экзамене).
- `POST /api/mock/:id/submit` — проверка `{ answers: { "1":"...", ... } }` → балл + разбор.

## 3.5. Авторизация
- **Родитель:** Firebase Email/Password **или Google** (signInWithPopup). При первом входе создаётся документ `families/{uid}` со школой.
- **Ребёнок:** без почты. Родитель создаёт ребёнку код + PIN. Технически создаётся служебный Firebase-аккаунт `код@synaq.kids` с паролем-PIN (через вторичный экземпляр Firebase, чтобы не разлогинить родителя). Ребёнок входит по коду + PIN.
- Роль определяется по домену почты (`@synaq.kids` → ребёнок).

## 3.6. Проверка ответов (открытый формат)
Ответ ученика нормализуется перед сравнением: обрезка пробелов, нижний регистр, запятая → точка, удаление `%` и частых единиц (км, м, см, кг, г, л, тг, га, °, мин). Так «32», «32%», «6,5»/«6.5» засчитываются корректно.

## 3.7. Безопасность (Firestore Rules)
- `waitlist` — разрешён только `create` (сбор почт), чтение запрещено.
- `families` — доступ только владельцу (родителю).
- `childIndex` — ребёнок читает свою запись; родитель создаёт.
- `results` — ребёнок пишет/читает свои; родитель читает результаты только своих детей (через `exists()`-проверку связи родитель→ребёнок).

## 3.8. Деплой
Один проект Vercel, Root Directory — корень репозитория. Корневой `vercel.json`: `buildCommand` собирает фронт (`frontend/dist`), функция `api/[...path].js` обслуживает `/api/*` через Express. Лендинг может деплоиться отдельным проектом (Root Directory = `landing`, Framework = Other).

Настройка Firebase (один раз): включить **Email/Password и Google** в Authentication; добавить домен сайта в **Authorized domains** (для Google-входа); создать Firestore (регион eur3, production mode); опубликовать `firestore.rules`.

## 3.9. Нефункциональные требования
- **Производительность:** банк задач статичен, отдаётся быстро; фронт — SPA.
- **Масштабируемость:** serverless-бэкенд; при росте — вынести бэкенд/БД на Supabase/Render.
- **Приватность:** данные детей минимальны (имя, класс, код); почты в waitlist закрыты от чтения; пароли родителей хранит Firebase.
- **Доступность:** mobile-first, крупные элементы управления.

## 3.10. Открытые вопросы / технический долг
- Ответы банка посчитаны вручную — сверить с официальным ключом РФМШ перед продакшеном.
- 7 задач с чертежами требуют визуальной сверки по рисунку (помечены).
- Детский вход «код + PIN» — упрощённый; для усиления защиты — перейти на Cloud Functions с кастомными токенами.
- Задачи с изображениями (чертежи) в движке с открытым ответом — требуют слота под картинку в UI.

## Приложение. Текущее состояние
- Банк РФМШ: 8 вариантов РФМШ-2025 (7 класс), ~243 задачи с ответами и разборами (+7 фигурных требуют рисунка); часть с чертежами (SVG/PNG).
- Банк БИЛ: 28 задач (формат A–E), оцифрованы из читаемого текста пробного теста; остальные — на изображениях (формулы/фигуры), требуют читаемого текста и ключа.
- Реализовано: онбординг с выбором школы, вход (почта / Google / ребёнок код+PIN), тренировка по темам с % решённого, еженедельный авто-мок, прогресс с историей и разбором, кабинет родителя, сохранение результатов (Firebase), школо-осознанность (РФМШ/БИЛ).
- Готовые школы: РФМШ (полностью), БИЛ (частично, 28 задач). НИШ — следующая волна.
